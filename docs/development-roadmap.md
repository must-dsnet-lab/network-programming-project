## 2. 清单一 · 高级向专家推进

专家路线把高级版的单会话控制扩展为 **双端在线、车端独占授权、显式交接、代次隔离和限时续约**。下面是供成员认领的实施草案。先定需要共同遵守的协议含义，再接网络并发和界面。 [README 协议待办](../README.md#protocol-checklist)

### 2.1 先固定五个概念

| 概念 | 由谁维护 | 需要写进协议约定 |
| --- | --- | --- |
| TLS 身份与连接 | 车端为每条已认证连接保留独立上下文 | 操作员身份与连接实例分开。相同账号新连入时，旧连接的迟到回调仍归旧实例 |
| 管理会话 | 车端建立，桌面用会话 ID 关联请求 | 连接关闭、复位、交接分别清理什么。校验失败返回明确的原因 |
| 控制权和授权代次 | 仿真线程串行裁决 | 任一时刻至多一个持有者。每次授予、回收或交接后的代次如何生成。重启后仍能区分旧运行期间的授权 |
| 控制权租约 | 车端单调时钟 | 何时开始、谁可续期、续期依据、何时到期。超时后按车端状态重申请 |
| UDP 窗口和序号 | 车端签发短窗并确认已接受序号 | 代次隔离旧授权，窗口限制时间有效性，序号限制同一控制流的重复与倒序。管理保活与有效控制计时分开 |

高级入口 `management_listener()` 顺序服务 TCP/TLS 连接，通过有界队列把操作交给 `process_one()`。专家入口 `expert_management_listener()` 支持两条连接，并继续由仿真线程串行处理请求。 [高级管理运行时](../src/rover/vehicle/management_runtime.py) · [专家管理运行时](../src/rover/vehicle/expert_management_runtime.py) · [现有控制保护](../src/rover/vehicle/control_guard.py)

**P5 当前裁决顺序。** 车端先检查已有锁存和 UDP 看门狗，再检查租约。仿真线程清理已知断开后，按入队顺序处理管理请求，并以实际处理时刻裁决续期。撤权使旧代次、密钥及窗口失效，清空目标和序号。新持有者以新的控制上下文重新使能。 [队列和租约规则](expert-control-authority.md#32-队列与租约边界)

### 2.3 一次正常交接和四类冲突

**演示主线。** A 已控制并运动 → A 显式归还 → 车端撤销 A、归零并记录 → B 取得新授权但暂不运动 → B 显式使能并应用目标 → 车端首次接受 B 的指令。管理请求编号用于匹配回复，授权代次用于判定当前持有者的有效指令。

| 在哪一环故障 | 要看到的结果 |
| --- | --- |
| 两端同时申请或同一申请重复到达 | 每轮一个确定的裁决结果，只有一个持有者 |
| A 交还后旧管理连接才关闭 | 只处理 A 旧连接的清理，B 的当前授权继续由车端核对 |
| 交接中 B 退出，或新持有者未使能 | 车辆保持零速，后续合法连接通过明确申请与使能恢复 |
| 旧数据晚到，或续约晚于到期 | 车端给出明确拒绝原因，过期资格不因网络恢复重新生效 |

**测量口径。** 交接耗时从车端收到有效请求到 B 首条控制获准。停车仍记录末条有效指令到首次零速，另保留保护触发时刻。租约记录最后成功续期、设定到期、实际撤销和归零。按同一车端时钟计算，用样本数、P50/P95 和失败轮次支撑结论。

**协议 S4/S5 边界。** 专家开发期间用本机或 VMware 验证。集中现场验收时，高级和专家按各自验收项留证。专家档的正式认定请以教师确认的要求为准。若课程还要求做可靠 UDP，可另开验证课题，选择可重试、需要确认的消息，单独测到达率和确认时延。实时速度与方向目标仍按最新有效值和时限处理。

#### 二维用户版 · 多桌面接入与自动遥测

在专家 P1–P7 的双端闭环基础上，随二维用户版的注册、登录与角色接入交付，再进入驾驶与三维体验验收。车端按部署配置启动一次，用户在桌面窗口登录后自动收到遥测。新窗口加入、退出或重连都由已运行的车端处理。

| 实施内容 | 通过条件 |
| --- | --- |
| 多桌面会话与角色 | 同一车端支持至少三个已登录桌面端同时在线。操作者可以申请控制权，只读角色可以接收遥测。到达部署容量时，新增连接得到可读提示，已在线会话继续运行 |
| 自动登记遥测 | 桌面自动分配接收端点，通过已认证会话向车端登记。车端只向通过权限与端点校验的接收端发送，并在断开或注销时清理，重连后重新登记。同机三个窗口各自收到车速和保护状态，另验 A、B 与只读观察端同时在线。两个场景通过图形界面连接，车端均使用同一份启动配置 |
| 独占控制与交接 | 同一时刻一个会话持有控制权。A 从 B、C 等在线候选者中选择交接对象，车端确认归零后授予选中的会话。新持有者显式应用后才起步。复验看门狗、急停和显式复位后的遥测确认与重新申请 |

**遥测地址和端口的识别方案。** 桌面打开一个 UDP 接收套接字，由操作系统分配空闲端口。登录后，桌面经 TLS 取得与当前会话绑定的短期登记凭证，再从同一个 UDP 套接字发送登记报文。车端校验凭证与角色，记录该报文实际到达时的来源 IP 和 UDP 端口，后续向这个地址发遥测。管理 TCP 和遥测 UDP 分别使用各自的端口。

验收覆盖同机窗口共享 `127.0.0.1`、各用不同 UDP 端口，以及局域网桌面使用不同 IP、可以使用同一 UDP 端口。重连时核对车端改用新登记的接收端点，旧登记随原会话清理。观察端在车端运行期间加入并开始收到遥测。

#### 二维用户版 · 车端管理 EXE

为部署和管理人员交付独立的 Windows 车端 EXE。界面按会话列出在线桌面，显示账号、角色、管理连接地址、登记的遥测地址和端口、最后活动时间及当前控制权。同一账号开的两个窗口分行显示。点开某个会话可查看经脱敏的近期事件，包括登录、遥测登记、控制权交接和断开。遥测状态按车端已登记地址及本地发送结果显示。若需要显示桌面实际收到遥测，应使用桌面端反馈核实。

验收时用车端管理界面启动服务，在运行中加入 A、B 和只读观察端。核对三条会话各自的地址和角色、控制权交接后的持有者，以及 B 断开重连后的在线状态和新遥测端点。管理员通过界面即可定位是管理连接、遥测登记还是发送环节出现异常。

| U7 | **三维场景与车体**。消费 U6 的车端遥测，接入车体场景和俯视或跟随视角 | 保留二维视图。平地轨迹可与正交投影核对，斜坡或高低落差中车体位置随 z 变化。交付同一遥测的 2D/3D 对照、坐标测例、模型资源和回退方式 |
| U8 | **驾驶反馈和最终发布复验**。U4–U7 连通后接入相机、车轮转动、姿态及可选声效 | 用真实遥测或计算状态驱动反馈。录制同版本的起步、滑行、制动、高度变化和故障恢复。交付版本化录像、实测图和可复现输入序列。用最终 Windows 包重测 U3 的全部场景并核对 2D/3D 资源 |

### 3.4 现有模型怎样演进

当前 `VehicleState` 保存平面位置、朝向和速度。数值控制使用 `apply_target()` 和 `advance()` 更新速度、朝向和位置。二维驾驶使用 `advance_driving()` 根据油门、刹车和方向按步长积分。后续三维遥测须明确 `z`、速度、朝向及可选姿态字段的生产者和单位。固定输入轨迹由车端生成，2D/3D 同时读取它。 [二维驾驶模型](../src/rover/core/driving.py) · [控制目标](../src/rover/core/control_target.py) · [遥测编解码](../src/rover/protocol/telemetry_codec.py)

模型原型将操纵状态和车辆状态分开。油门与刹车作为输入，车端计算纵向加速度，按仿真步长积分速度与位移。第一阶段在平地验证驱动、滚动阻力和制动，再加入坡度影响。方向摇杆映射转向量，转向随车速和输入共同决定。车辆位置与姿态由车端产生，GUI 通过遥测驱动视图和反馈。

开发时先用低成本场景核对坐标和操控。平地确认 `z` 恒定，带高度差的路线确认 `z` 随时序变化。模型先验证油门带来的速度渐变、松油门后的滑行、刹车带来的有限停止距离和方向回中的行为，再增加场景和渲染质量。

**驾驶反馈。** 用实际速度、加速度和姿态驱动相机与车体反馈。可同时记录加速度变化，检查油门或刹车从零跳到满量时的体感是否突兀。若之后选用支持振动或力反馈的设备，再单独校准对应反馈。

| 固定输入用例 | 应看到的状态变化 |
| --- | --- |
| 静止时逐步加油，随后保持油门 | 连续记录从零起步的速度和加速度。速度变化受模型限制，曲线能用同一输入复跑 |
| 运动时松油门，再单独踩刹车 | 滑行和主动制动分别有速度曲线。记录刹车时刻、停止时刻和两点间距离 |
| 在平地、斜坡以相同操纵运行 | 平地高度恒定，斜坡高度从车端变化。二维投影和三维轨迹能对照，转向跟随实际位置与朝向 |

**停车分两种验收。** 常规驾驶关注加速、滑行、制动曲线和停止距离。故障保护关注车端撤销控制、进入锁存以及最终归零。新模型需要分别记录保护触发和实际归零时刻。若引入渐进的紧急制动，先评审保护口径及原有时限，再以实测更新报告。

**体验开发约定**

- GUI、后台网络和仿真模型职责各自明确。常规布局和图形化连接可先做，遥测字段与控制输入改动在共享接口上单独评审。
- 界面保留真实连接、输入是否生效、遥测是否过期和车端保护反馈。操作员的回中、松开油门和踏刹车分别有定义。
- 使用正式 TLS 校验和权限判断。连接配置、日志与截图按项目证书和凭据约定处理。
- 可按块参考组员已有布局、地图操作和导出方案。按当前 `main` 独立适配，每项都留对应复现材料。
