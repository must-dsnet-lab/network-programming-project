# 项目开发规范

适用于在本仓库工作的成员及 AI 助手。仓库根目录的 [AGENTS.md](../AGENTS.md) 是给支持读取仓库指令的工具的入口。其他工具可把本文件路径和本轮任务一起交给 AI。

[README 与当前待办](../README.md) · [开发路线与任务](development-roadmap.md) · [高级版运行函数索引](runtime-reference.md) · [验收补充](verification.md)

## 1. 开工与分工

- 写清任务、目标行为、依赖、允许修改的范围和通过条件，记录当前分支及基线提交。先检查已有改动、冲突中的 PR、相关测试和实际入口，再决定是在现有模块补齐还是单独分支试验。
- 一轮围绕一个明确目的。可分开的功能、实验、图和文档按各自目的整理。相互依赖的最小改动可放在一起，说明联系。改动涉及多个成员的模块时，先确定共享接口、兼容行为和验收分工。
- 沿用当前任务指定的协作方式。讨论轮输出方案和取舍，教学轮给可定位的代码片段及测试入口，授权执行轮可直接完成实现和验证。现场关键操作由负责人或约定的测试人执行，AI 可准备命令、采集方案、预检和后续数据核对。
- 需要变更课程范围、系统安全行为或他人负责的接口时，向负责人说明影响和待定决策。课程档位以教师确认及交付证据为准。

## 2. 代码与层间职责

| 层或模块 | 改动约定 |
| --- | --- |
| `src/rover/protocol/` | 管理、控制、遥测格式集中在编解码层。新增字段注明类型、单位、版本和兼容方式，覆盖缺失、无效和旧格式行为 |
| `src/rover/transport/` | 负责 TCP 分帧、UDP 收发及实验转发。保留主应用与实验工具的实际接入边界 |
| `src/rover/vehicle/` | 车端统一裁决认证后的管理动作、会话、控制报文、看门狗及保护恢复。网络线程交接状态操作，仿真线程按确定顺序处理。改动涉及重连、关闭、过期和并发时，核对控制权、有效目标及清理后的状态 |
| `src/rover/core/` | 保存车辆状态和运动计算。明确坐标、单位、步长与输入范围。操纵意图、仿真状态和显示状态各用对应的数据 |
| `src/rover/desktop/` | 界面提供控制意图并显示车端状态。Qt 主线程更新控件，后台负责网络和控制周期。界面从遥测与会话状态呈现实际连接、运动、停车和保护结果 |

- 复用已有类型、状态和入口。写清楚命名与控制流，注释解释协议约束、并发边界或设计取舍。接口变更从正常入口验证，覆盖旧配置、断连重试与失败清理等受影响路径。
- 安全模式的证书校验、车端控制准入、故障锁存和显式恢复按当前契约执行。正常停车、停止发包、急停和复位按不同动作验收。影响这些语义的变更应同步说明旧行为、目标行为和回归用例。
- 按现有 `src/rover` 包布局维护源码。日常供组员复现的正式入口是 `python -m rover.vehicle.app` 和 `python -m rover.desktop.app`，`examples/` 用于示例和实验。调整运行依赖时核对 `pyproject.toml` 与 `requirements.txt` 的一致性。

## 3. 开发验证与验收证据

**核心行为按 RED → GREEN → 必要重构推进。** 对协议、安全规则和运行时行为先写可执行的预期，确认 RED 由待实现行为触发。最小实现后确认新增和相关旧用例通过。若需要重构，主动复跑相关测试。纯文档核对链接、显示和数据，导图检查源文件及实际渲染，界面变更做相关自动化和实际界面检查。历史实践见 [README 的测试驱动开发](../README.md#development-method)。

Windows 现有全量回归入口如下。专项测试选取本次影响的测试模块。

```powershell
$env:QT_QPA_PLATFORM = 'offscreen'
.\.venv\Scripts\python.exe -X utf8 -B -m unittest discover -s tests -t . -q
```

| 场景 | 记录与判定 |
| --- | --- |
| 候选预检、替身和自动化 | 写明命令、目标、实际通过/失败项与替身边界。联调前先核对正式入口能启动 |
| 真实进程联调 | 标明本机回环、宿主机与 VMware，或物理双机，记录各端版本、角色和所用链路。按用例观测启动、连线、实际状态、拒绝、停车和退出清理 |
| A/N 验收与实验 | 沿用 `local/a-tests/`、`local/n-tests/` 的编号归档。保存原始日志、配置、版本、实验执行人和必要截图。按真实轮次注明成功、失败、未生效及待补项 |
| 时间和统计 | 标明计时起止事件、单位、样本数、环境和相关限制。按实验使用同一时间基准，区分故障发生、被检测、车端归零与恢复起步。统计结论能追到对应原始记录 |
| 汇报与完成标记 | 记录命令、实际结果、尚待验证项和已验证 Git 版本。打钩对应任务的验收条件及交付物已满足，有可追溯提交、PR 或记录。预检、实现完成及现场验收各按证据说明 |

物理双机、真实断网与恢复、关键 GUI/操纵演示等由约定的操作人进行。记录正常及反例，时间或状态证据不足时标为待补。公开 README 和报告引用可公开的结果、测量口径与复现入口。原始实验材料留在本地约定目录。

## 4. README 与导图

### README

- 首页提供项目入口、可勾选的阶段待办及详细路线和规范链接。任务的完整依赖、验收条件和交付物归在路线文档，README 清单便于组员快速查看。
- 正文按实际开发顺序再按主题分层。新增内容放在最相关的阶段和模块。较长章节用运行流程、命令、结果、常见问题或设计取舍组织。短要点和对照表用于降低查找成本。
- 调整层级时保留已有解释、可复现命令、真实数据、图表和链接锚点。当前状态与旧实验分别写明适用阶段，更正事实时保留核对依据。改动命令时核对入口、参数和适用环境。

### 技术导图

- 当一张图能说明阶段里难以读懂的调用、时序、线程交接、协议边界或实验拓扑时，先向负责人说明适合在哪一章用图、它要回答什么。新增导图由负责人确认后制作，本轮明确要求的导图按任务推进。
- 用源码、接口和实测记录核对节点。运行图优先画真实入口、实际函数、调用方向、通道、跨线程交接、分支及回路。图例说明颜色、实虚线及方向，用必要的短标签承载信息。计划图和运行图各自标明对应阶段。
- 主线先建立阅读顺序，细节过多时提供可展开的模块索引或独立子图。先按常用预览尺寸检查小字，再检查放大图。增大文字和子框，利用留白为标签腾出空间，核对无截断、重叠、遮挡或错箭头。
- 保存可编辑源和项目约定的产物。Mermaid 留源代码块，生成图同步保留生成脚本、SVG 和高清 PNG。变更图的路径、标题或函数时，同步核查 README、索引、图源和最终渲染链接。[README 图源管理](../README.md#diagram-maintenance) · [运行图及展开索引](runtime-reference.md)

## 5. Git、PR 与公开范围

- 从已核对的基线建功能分支，按可独立复现或审查的目的组织提交。提交信息写清动作和对象，沿用仓库的 `feat:`、`fix:`、`refactor:`、`docs:` 等用法。已有他人改动时限制提交范围，清楚区分本轮工作与已有内容。
- 先看 `git status --short --branch` 和工作区差异，用 `git add -- <已核对的路径>` 暂存，再看 `git diff --cached --stat`、`git diff --cached` 和 `git diff --cached --check`。路径重命名或迁移时同时核对旧路径和新路径。
- 提交、推送、创建 PR 或合并均使用适用于当前操作的明确授权，已有授权继续有效。上传协作采用功能分支和 PR，合并由负责人安排。处理有冲突的 PR 时先对照双方的接口、测试、配置与验收记录，保留能够证实的行为。待审 PR 的描述和实际改动共同核对。
- 私钥、真实凭据、会话密钥、`local/` 下的原始实验数据、个人资料、本地环境、缓存、构建产物及无关项目文件留在本地。公开示例使用占位值，截屏、日志摘要和附件同样核对敏感信息。源码、测试、复现命令、经过核对的图源和文档按任务提交。

**PR 交接清单**

- [ ] 任务编号或目标、基线、负责人和适用范围已写明。
- [ ] 变更可由正式入口或明确条件复现，注明兼容与安全行为的变化。
- [ ] 已列实际测试命令、结果及证据位置，待人工或跨机验证有明确责任人。
- [ ] README 清单、相关运行说明、索引与导图已按影响范围同步。
- [ ] 暂存差异对应当前任务，公开材料已核对。

## 6. 给 AI 的任务模板

```text
先读 AGENTS.md 与 docs/development-standards.md。
仓库基线 <分支/提交>。本轮任务 <编号及可观察目标>。
本轮由你 <讨论/提供代码片段/实现/验证>，可改 <文件范围>。
动手前核对正式入口、已有实现、其他人改动以及测试。
通过条件 <行为、复现命令及证据>。我或指定组员负责 <现场验收>。
报告实际修改、运行命令、结果、出现的问题、还待验证什么。
Git 授权 <只编辑/可提交/可推送与建 PR/可合并>，以本轮明确约定为准。
```

AI 报告中的完成状态须对应可复核的代码、可重现的执行结果和本轮授权。对存在分歧的接口或风险，写出需要负责人决定的具体事项。交付时给出主要设计、修改入口、验证证据与演示要点。
