# 组员集中验收清单

建议在同一次组内验收中固定 Git 提交，再依次核对自动化、可复现的本机对照和现场双机。执行人按用例编号回填结果。历史开发证据见 [P1–P6 复跑索引](expert-control-authority.md#组员复跑索引) 和 [高级 A/N 实验](../README.md#advanced-acceptance-status)。

## 1. 开测前记录

- 记录 `git log -1 --oneline`、各端系统、Python 版本及连接拓扑。注明 Windows 本机回环、VMware 或物理双机。
- 车端日志使用新文件。两端分别记录证书使用的服务器名称、管理与控制端口、遥测端口。使用实验账号，交回的记录中保留账号名即可。
- 现场安排车端、操作台 A 和操作台 B。只有两台物理电脑时，在车端所在电脑启动一个操作台，另一个放在第二台电脑上。高级和专家模式预配各遥测端点，用户版记录登录后车端登记的端点。

## 2. 组内复跑

| 编号 | 操作 | 通过条件及证据 |
| --- | --- | --- |
| R01 | 执行 [Windows 全量回归](../README.md#environment)。额外核对 [P7 进程内准入测试](expert-control-authority.md#101-运行对照) | 全量命令退出码为 0。保存版本、命令和汇总结果 |
| R02 | 按 [P7 对照](expert-control-authority.md#101-运行对照) 各跑高级、专家三轮 | 每轮都能起步、正常停车、再次起步，再从 GUI 同义的停发操作触发看门狗。提交车端 CSV、汇总和失败轮次 |
| R03 | 按 [P6 双端步骤](expert-control-authority.md#91-组员本机复现) 跑一次 A 到 B 的交接 | A 独占控制，B 可见持有者且不可应用。车端确认零速再授予 B 新代次。B 显式应用才起步，归还后停车。保存两端事件与车端 CSV，附一段录像 |
| R04 | 按 [P5 到期与断流](expert-control-authority.md#81-组员本机复现) 分别验证两个计时器 | 有效 UDP 持续时停止续期，车端到期归零且保护未锁存。租约有效时停发，车端归零并锁存。复位和重新申请后仍需显式应用目标 |

| R06 | 在无项目开发环境的 Windows 解压 [Windows 桌面包](../README.md#desktop-windows-starter)，点开三个入口 | 本地模拟能起步、停车、关窗和重开，当前用户目录有日志。连接车端使用公开 CA，错证书显示失败，正确证书可登录及保存公开配置。配有固定第二路遥测的车端可以给「只读观察（手动遥测）」送数据。交回 Windows 版本、打包提交、EXE 哈希及实际结果 |
| R07 | 用 [二维用户版 Windows 包](../README.md#two-dimensional-user-edition) 启动车端，先注册四个账号，再将 A、B、C 改为操作者，D 保持观察员。角色更新后重新登录 | 四端都显示「遥测可用」。观察员看车速和轨迹，A 从 B、C 中选交接对象，确认归零再显式应用。B 断开重连后，车端表显示旧会话断开及新端点。重启车端再核对账号和角色，保存系统、拓扑、版本及脱敏记录。无开发环境复跑时同时核对车端管理 EXE 能启动、读库并启停服务 |
| R08 | 按 [二维驾驶](../README.md#desktop-2d-driving) 依次加油、转向、松油和踩刹车。再复跑失焦、停发、急停、复位和断开重连 | 观察端收到对应速度和方向。失焦后车制动且输入停用，重新应用才恢复。停发和急停归零锁存，复位或重新连接保持静止。附固定输入 CSV、速度／加速度曲线和现场短录像 |

## 3. 物理双机与实际断网

跨机连接使用与实际车端地址或 DNS 名称相符的证书。高级和专家模式按 [跨系统启动与地址配置](../README.md#vmware-lan-acceptance) 和 [P6 正式入口](expert-control-authority.md#91-组员本机复现) 配置固定遥测目的地。用户版按 [4.8 部署和登录](../README.md#two-dimensional-user-edition) 启动车端，通过登录会话自动登记桌面端点。

| 编号 | 操作 | 通过条件及证据 |
| --- | --- | --- |
| A01 | 两台物理电脑运行高级模式，在桌面应用非零速度 | TLS 认证、UDP 控制、车端运动和桌面遥测四项均可观察。记两台电脑的角色及网络方式 |
| A08/A09 | 小车在仿真环境中运动时，由操作人断开桌面端的实际网络连接，保持车端运行，再接回 | 车端归零，接回后保持零速。记录先发生的是会话撤销还是看门狗。重建管理连接，若锁存则显式复位，再按操作流程使能并应用一次新目标 |
| P7-LAN | 在两台物理电脑的拓扑上复跑 R03、R04，按实际角色记录 | 有双端授权变化、零速交接、两种停车与恢复证据。保留端侧日志、车端 CSV 和短录像 |
| 用户版 LAN | 用同一版本的两端程序在两台物理电脑复跑 R07。把至少一个操作者和一个观察窗口放在另一台电脑，允许其余窗口与车端同机 | 会话表记录实际遥测目的 IP 与端口，各窗口都有实时读数。完成一次跨机零速交接与一次重连，核对新登记和旧会话清理。留端点、角色、速度和事件的脱敏记录 |

### 3.1 用户版同一热点双机实测（2026-11-23）

**环境与结果。** Windows 电脑运行车端管理 EXE 和本机操作台，组员在另一台 macOS 电脑运行「用户版（自动遥测）」桌面端。两台物理电脑接入同一部手机的热点，管理使用 `19177/TCP`，控制使用 `9999/UDP`。Mac 终端实测管理端口可达，组内现场反馈已能完成跨机控制权交接。当前记录覆盖双机交接子项。两端构建版本、归零与重新应用的状态日志，以及多端观察和重连后旧登记清理的证据仍待补录。

| 排查阶段 | 现场现象与处理 |
| --- | --- |
| 地址与证书 | 初始配置使用回环地址，另一台电脑无法通过它访问车端。用 Windows `ipconfig` 确认热点下的 WLAN IPv4，车端在该地址启动，桌面填写同一目标地址。车端选择包含该 IP 的服务器证书，Mac 导入同批公开 CA，证书名称留空时按连接地址校验。 |
| 管理 TCP | Mac 起初报无法连接管理端口。在 Windows 管理员 PowerShell 添加 TCP 入站允许规则，范围限定车端 WLAN IPv4、本地子网及管理端口。Mac 执行 `nc -vz -G 5 VEHICLE_IP 19177` 后得到 `succeeded`，其中 `VEHICLE_IP` 替换为实际地址。 |
| UDP 登记与控制 | 管理连通后，Mac 报「未收到车端遥测登记确认」。车端动态 UDP 端口负责登记，控制指令走单独的控制 UDP 端口。按实际监听进程的 EXE 路径，在当前网络配置文件中放行来自本地子网、发往车端 WLAN IPv4 的 UDP 入站。 |
| 管理员终端操作 | 普通 PowerShell 写入防火墙规则时返回 `Windows System Error 5`。打开管理员 PowerShell 后，多行粘贴顺序错误又触发了语法错误。将查询监听进程和添加规则写入本地 PowerShell 文件，再用单行 `powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File` 调用。最终 UDP 规则输出为 `Enabled: True`、`Direction: Inbound`、`Action: Allow`、`Profile: Public`，队友重连后反馈可完成交接。 |

**换网后的另一次尝试。** Windows 切回校园 WLAN 后，车端与 Mac 表单填的是同一个车端内网地址，两端均填写管理端口 `19177` 和控制端口 `9999`。Windows 本机桌面显示 TLS 已认证，车端表只见来自本机地址的会话。Mac 提示「无法连接车端。请检查网络、车端地址和管理端口」。旧热点规则绑定旧地址。校园网下的双机路由和新地址入站规则尚待核对。现有截图记录了本机可用与远端失败，具体原因有待复测。

**复测顺序。**

1. 确认两台电脑之间存在到车端的网络路径。同一个允许互访的热点可复跑上一轮。不同接入网可通过双方都能访问的虚拟局域网联调。用 Mac 对当前车端地址和实际管理端口跑 `nc`，记录原始返回值。
2. 管理端口不通时，核对车端绑定及服务是否运行，再查 Windows 防火墙规则里的本机地址、端口、程序路径、网络配置文件和远端来源范围。旧规则可能因换网而不再匹配。
3. 管理端口可达后，检查当前车端证书的身份及对应 CA，再登录并观察车端会话表。若只卡在遥测登记，检查协商的动态 UDP 端口和控制 UDP 的入站规则，并核对登记报文和 TLS 使用同一客户端来源 IP。收到遥测后再录制交接和重连。

## 4. 交回格式

每条记录使用 `用例编号 · Git 提交 · 执行人 · 环境 · 通过／失败／待测 · 证据位置`。本机、虚拟机、物理机分别记录。测时间用同一份车端 CSV 的 `elapsed_s`，并注明起止事件。用例未达到通过条件时保留日志和操作步骤，便于复查。

公开报告可引用脱敏结果、汇总表和复现入口。原始日志、录屏、凭据、私钥和本地环境保存在组内约定的位置。物理现场完成后再更新 [README 的现场勾选项](../README.md#protocol-checklist)。
